# 샌드박스 카메라 구현

## 기존 코드와 변경 범위

시작 코드의 파일 구조를 유지하면서 확장했다. `d04-inspection-model.js`의 건물, 명판의 위치·크기·내용은 그대로 사용한다. `demo.js`의 행렬 연산과 WebGL 유틸리티도 유지한다. 비교 원본인 `week4/baseline`은 수정하지 않는다.

- `d04-inspection-controls.js`: 기존 quaternion 트랙볼을 eye 위치와 yaw/pitch 기반 자유 이동으로 변경했다.
- `d04-inspection-viewer.js`: 기존 렌더링에 매 프레임 이동 갱신을 연결하고 카메라 정보를 표시한다.
- `d04-inspection-student.js`: 기존 UI 확장 지점에 이동 속도·FOV·마우스 감도와 탐색 시작 버튼을 구현했다.
- `index.html`, `demo.css`: 조작 안내, 잠금 상태, 조준점, 반응형 패널을 구성했다. 기존 8개 관찰 과제와 측정 기능은 유지했다.

## 실행과 조작

저장소 루트에서 `python -m http.server 8000`을 실행한 뒤 `http://localhost:8000/week4/improved/`에 접속한다. 외부 라이브러리나 빌드가 필요 없다.

| 입력 | 동작 |
| --- | --- |
| 탐색 시작 버튼 | 마우스를 잠그고 연속 회전을 시작 |
| W / S | 현재 시선 기준 수평 전진 / 후진 |
| A / D | 현재 시선 기준 왼쪽 / 오른쪽 이동 |
| Space / 왼쪽·오른쪽 Shift | 월드 +Y 상승 / −Y 하강 |
| 마우스 가로 이동 | 현재 위치에서 좌우 회전 |
| 마우스 세로 이동 | 현재 위치에서 상하 회전 (±89°) |
| Esc | 마우스 잠금 해제, UI 사용 |
| 화면 클릭 및 드래그 | 키보드 이동 활성화 및 잠금 없는 상하좌우 회전 |
| Home / 전체 보기 | 현재 화면 비율에 맞춰 전체 모델을 보는 위치로 복귀, FOV 60° |

마우스를 위로 움직이면 위를, 아래로 움직이면 아래를 바라본다. WASD는 시선의 수평 방향을 기준으로 이동하며, 실제 높이는 Space/Shift로 조절한다. 충돌·중력은 없으므로 벽과 바닥을 통과할 수 있다. 속도는 기본 4 m/s, 0.2~12 m/s로 조절한다. 슬라이더 등 UI에 포커스가 있으면 이동 키를 처리하지 않는다. 창 포커스 상실, 탭 전환, 잠금 해제 시 입력을 비운다.

## eye, target, up, 회전 중심

좌표 단위는 제공 모델과 같은 m이며 월드의 위쪽은 +Y이다. 매 프레임 `lookAt(eye, target, [0,1,0])`으로 뷰 행렬을 만든다.

`eye`는 카메라의 실제 위치다. 수평 회전각 yaw를 θ, 상하 회전각 pitch를 φ라고 할 때 다음과 같이 정한다.

```text
forward = (sin θ × cos φ, sin φ, −cos θ × cos φ)
horizontalForward = (sin θ, 0, −cos θ)  // WASD 이동용
right   = (cos θ, 0,  sin θ)
up      = (0, 1, 0)
target  = eye + forward
```

`target`은 현재 위치에서 시선 방향으로 1 m 앞의 가상 점이다. 모델의 특정 지점에 고정하지 않으며, 이동하면 eye와 함께 움직인다. 1 m는 방향을 표현하기 위한 거리로 확대율이나 초점 거리를 뜻하지 않는다.

회전 중심은 매 순간의 `eye`이다. `θ += movementX × sensitivity`, `φ -= movementY × sensitivity`로 각도를 갱신하고 target을 다시 계산한다. 기본 감도는 0.0025 rad/px이다. 회전만으로 eye는 바뀌지 않는다. φ를 −89°~89°로 제한해 수직 시선과 up이 평행해져 lookAt 계산이 불안정해지거나 화면이 뒤집히는 것을 방지한다. `lookAt`에 전달하는 월드 up은 항상 `(0,1,0)`이며 roll은 없다. 상하 회전 시 실제 화면의 위쪽 벡터는 월드 up을 시선에 수직인 평면에 투영한 방향이다.

키 입력으로 `W−S`, `D−A`, `Space−Shift` 성분을 만든 뒤 벡터 길이를 정규화하고 `speed × dt`를 곱해 eye에 더한다. 대각선과 상승을 함께 눌러도 총속도는 동일하다. dt의 단위는 초이고, 긴 프레임에서 갑자기 멀리 이동하지 않도록 한 프레임의 dt를 최대 0.05초로 제한한다. 지속적으로 20 FPS 미만이면 실제 이동 속도가 설정값보다 느려질 수 있다.

## 초기 eye와 전체 보기

제공된 `model.bounds`를 이용한다. 경계 상자의 중심 `C=(min+max)/2=(3.25,4.575,0)`, 이를 감싸는 구의 반지름 `R=length(max−min)/2`를 구한다.

1. 수직 FOV를 60°, 초기 yaw를 −0.6 rad, pitch를 0으로 설정한다.
2. 실제 캔버스의 가로/세로 비율을 `aspect`로 구한다.
3. 수직 반화각 `αy=FOV/2`, 수평 반화각 `αx=atan(tan(αy)×aspect)` 중 작은 값을 사용한다.
4. 거리 `d=1.1×R/sin(min(αx,αy))`로 약 10%의 여유를 둔다.
5. `eye=C−forward×d`로 놓는다. 수평 시선이 C를 통과하므로 전체 모델이 화면에 들어온다.

C는 전체 보기의 배치 기준이다. 실제 회전 중심은 여전히 eye이고, target도 `eye+forward`이다. 창 크기를 바꿀 때는 사용자의 위치를 유지하며, Home을 누르면 새로운 화면 비율에 맞춰 다시 배치한다.

## FOV와 투영

수직 FOV는 기본 60°, UI 범위는 30~90°이다. 전체 공간 탐색과 세부 관찰 사이의 절충값으로 60°를 선택했다. 작은 FOV는 명판을 크게 보여 주고 큰 FOV는 주변을 넓게 보여 준다. FOV 변경은 eye와 target을 움직이지 않는다. 실제 캔버스의 비율과 FOV를 기존 `M4.perspective`에 전달한다.

near는 작은 명판에 접근할 수 있도록 0.02 m로 설정했다. far는 최소 180 m이며, eye와 모델 중심 사이의 거리 + 경계 구 반지름 + 10 m 이상으로 계산해 멀리 이동해도 모델이 원거리 절단면 밖으로 사라지지 않도록 한다.

## 확인 방법

상하 회전 추가 후 Headless Chrome에서 7개 항목을 검증했다: 위쪽·아래쪽 마우스 입력 방향, 양쪽 각도 제한 및 WebGL 렌더링, yaw/pitch 동시 회전, 위아래를 볼 때의 수평 이동 높이·속도, Home 초기화, 드래그의 상하좌우 회전과 종료 처리. 잠금 상태의 이동 이벤트와 드래그 이벤트는 자동 검증에서 합성했다. 모델 파일의 SHA-256은 baseline과 동일하고 baseline의 Git 변경 사항은 없다.

상하 회전 추가 전에는 카메라·UI 자동 검증 16개와 실제 브라우저 입력을 통한 잠금 획득·회전·Esc 해제·드래그 후 W 이동 유지의 4개 항목을 확인했다. 당시 1440×1000 화면 캡처와 390px 너비의 가로 넘침 검사도 수행했다.

- W/S, A/D가 서로 반대이고, 회전한 뒤에도 시선 기준으로 이동하는지 확인한다.
- Space와 양쪽 Shift로 높이를 바꾸고, 마우스 세로 이동 시 eye·높이·월드 up을 유지하면서 target의 높이가 변하는지 확인한다.
- 잠금과 드래그 모두 상하좌우 회전, pitch ±89° 제한, Home의 pitch 초기화를 확인한다.
- 위아래를 보면서 WASD로 이동해도 수평 이동 속도와 높이가 유지되는지 확인한다.
- FOV 변경 시 위치 유지, Home 복귀 시 FOV 슬라이더 동기화를 확인한다.
- 이동 키를 누른 채 창 전환 또는 UI 클릭 후 돌아왔을 때 이동이 멈추는지 확인한다.
- 전체 모델과 기존 명판이 유지되는지, 작은 창에서도 UI와 캔버스에 접근할 수 있는지 확인한다.

기존 직교 투영 API는 렌더러에 남아 있다. 이번 조작 UI는 원근 투영을 사용하므로 O1/O2의 정확한 직교 비교를 위한 별도 뷰는 추가하지 않았다.
