## 두 버전의 실행과 조작법

### 기본 버전

![기본 버전 전체 화면](images/baseline-overview.png)

건물을 중심으로 카메라가 회전하는 트랙볼 방식이다. 회전과 화면 기준 평행 이동, 카메라와 중심 사이의 거리 조절을 조합해 관찰한다.

| 입력 | 동작 |
| --- | --- |
| 마우스 드래그 | 트랙볼 회전 |
| Shift + 드래그 / 오른쪽 버튼 드래그 | 화면 기준 평행 이동 |
| 마우스 휠 | 회전 중심과 카메라 사이의 거리 조절 |
| 방향키 | 회전 |
| + / − | 거리 축소 / 확대 |
| Home / 전체 보기 | 초기 카메라로 복귀 |
| 측정 시작 / 초기화 | 경과 시간과 조작 횟수 초기화 |

키보드 조작은 캔버스에 포커스가 있을 때 사용한다. 기본 FOV는 45°이며 휠은 FOV가 아니라 거리를 바꾼다.

### 개선 버전

![현재 개선 버전의 원근 관찰 화면](images/improved-current.png)

현재 개선 버전은 `원근 관찰`, `전면 직교`, `측면 직교` 버튼으로 관찰 방식을 전환한다. 원근 관찰은 기본 버전의 드래그·평행 이동·휠 조작을 유지하면서 회전을 좌우로 제한했다. 오른쪽에는 P1~P6 명판 목록과 O1/O2 직교 비교 버튼을 배치했다.

원근 관찰의 조작법은 다음과 같다.

| 입력 | 동작 |
| --- | --- |
| 마우스 좌우 드래그 / 좌우 방향키 | 회전 중심을 기준으로 좌우 회전 |
| Shift + 드래그 / 오른쪽 버튼 드래그 | 화면 기준 평행 이동 |
| 휠 / +·− 버튼 | 회전 중심과 카메라 사이의 거리 조절 |
| Space / 구조물 반투명 버튼 | 명판을 제외한 구조물 반투명 토글 |
| 화면의 명판 / 번호 클릭 | 회전 중심을 명판으로 옮기고 정면으로 접근 |
| 오른쪽 P1~P6 버튼 | 해당 명판으로 이동. 보이지 않으면 반투명·전체 보기를 거쳐 접근 |
| O1 / O2 버튼 | 비교 대상을 포함하는 전면 / 측면 직교뷰로 전환 |
| Home / 전체 보기 | 전체 모델을 보는 위치로 부드럽게 복귀, FOV 45° |
| 측정 시작 / 초기화 | 경과 시간과 조작 횟수 초기화 |

반투명 상태에서는 구조물 뒤의 명판도 클릭할 수 있다. 선택한 명판에는 초록색 외곽선을 표시하고, 사용자가 카메라를 조작하면 해제한다. 자동 접근 중에는 외곽선을 유지한다. 원근뷰의 상하 회전은 사용하지 않으며 높이는 평행 이동으로 조절한다.

직교뷰에서는 회전을 고정하고 화면을 평행 이동한다. 전면은 −Z 방향, 오른쪽 측면은 −X 방향을 바라본다.

| 직교뷰 입력 | 동작 |
| --- | --- |
| W / S 또는 위·아래 방향키 | 카메라를 화면 위 / 아래로 이동 |
| A / D 또는 좌우 방향키 | 카메라를 화면 왼쪽 / 오른쪽으로 이동 |
| 드래그 | 장면이 손을 따라 움직이도록 평행 이동 |
| 휠 / 확대·축소 버튼 | 직교 투영의 표시 범위 조절 |
| Space | 구조물 반투명 토글 |
| Home / 전체 보기 | 현재 직교뷰의 중심과 표시 범위까지 부드럽게 복귀 |
| 원근 관찰 버튼 | 직교뷰 전환 전 원근 카메라 상태로 복귀 |

전면과 측면의 이동·확대 상태는 각각 유지한다. 직교뷰에서 Home을 눌러도 저장된 원근 카메라는 바뀌지 않는다. 다만 명판을 선택하면 해당 명판을 새 원근 관찰 대상으로 삼는다. 상태는 페이지가 열린 동안 유지되며 새로고침하면 초기화된다.

## 기본 버전의 관찰 결과와 불편

### 지점별 관찰 결과

먼저 **관찰 위치를 지정한 재현 캡처와 모델 데이터**로 각 지점에서 확인할 내용을 정리했다. 현재 개선 버전의 접근 방식과 직접 사용한 소감은 뒤의 개선 전후 비교에 정리했다.

| 지점 | 관찰 목표 | 확인한 결과 | 기본 방식에서 필요한 조작 |
| --- | --- | --- | --- |
| P1 본관 입구 | 동 이름과 층수 | `ENTRY A`, `LEVELS 3` | 전면으로 회전하고 안내판에 접근 |
| P2 1층 안쪽 밸브 | 식별 번호와 상태 | `V-07`, `OPEN` | 실내 표지가 보이는 방향으로 중심 이동 후 거리 조절 |
| P3 2층 제어함 | 회로 번호와 전압 | `B-12`, `24 V` | 2층 높이로 평행 이동하고 작은 명판 확대 |
| P4 옥상 서비스 장치 | 이름과 점검 주기 | `FILTER`, `30 DAYS` | 옥상이 보이도록 회전하고 표지 앞쪽으로 접근 |
| P5 본관 뒤쪽 배관 | 용도와 유량 | `RETURN`, `8 L/min` | 건물 뒤로 돌아가 명판의 글자가 있는 면을 관찰 |
| P6 별관 펌프 | 제한 온도 | `LIMIT`, `80 C` | 별관으로 중심을 옮기고 명판에 접근 |
| O1 전면 패널 | A·B의 폭과 상단 높이 | 둘 다 폭 1.2 m, 상단 y=3.4 m | 정확한 비교에는 전면 직교 투영이 필요 |
| O2 측면 장치 | 어느 장치가 +z로 더 돌출되는가 | A의 전면 z=1.0 m, B는 z=0.4 m. A가 0.6 m 더 돌출 | 정확한 비교에는 오른쪽 측면 직교 투영이 필요 |

O1/O2의 수치는 모델 좌표와 크기에서 계산한 값이다. 화면에서 길이를 직접 측정한 결과는 아니다. 기본 버전에는 직교 투영 전환 버튼이 없지만, 현재 개선 버전에서는 전면·측면 직교 버튼으로 비교할 수 있다.

### 직접 느낀 불편

| 항목 | 불편했던 점 | 동작 원인과 관찰에 미친 영향 |
| --- | --- | --- |
| 1 | **회전 중 화면의 위쪽이 달라질 수 있다.** | 기본 트랙볼은 eye와 up을 함께 회전시킨다. 층과 기둥이 기울어진 상태에서는 위아래 방향을 다시 파악해야 한다. |
| 2 | **관찰 지점과 회전 중심이 다를 수 있다.** | 초기에 중심은 `[3,3,0]`이다. P5 뒤쪽이나 P6 별관을 관찰하려면 회전뿐 아니라 중심 이동도 필요하다. |
| 3 | **화면 기준 이동과 실제 높이 이동이 다르다.** | Shift 드래그는 카메라의 right/up 방향을 사용한다. 카메라가 기울어지면 화면 위로 이동하는 것이 월드 +Y 상승과 같지 않다. |

## 사용자와 관찰 목표, 대안 비교

### 의도 — 무엇을 만들고 싶었는가

사용자는 시설의 외형뿐 아니라 내부·옥상·뒤쪽의 작은 명판을 확인하려는 관찰자로 설정했다. 기본 카메라 조작을 유지하면서 원하는 지점을 빠르게 찾아 세부 구조를 살펴보는 상황을 대상으로 한다.

목표는 P1~P6에서 글자를 읽을 수 있는 위치와 방향을 찾고, O1/O2에서 크기와 돌출 관계를 판단하는 것이다. 제공 모델을 확대하거나 명판을 별도 답 목록으로 대체하지 않고, 카메라와 입력 방식을 바꾸는 데 집중했다.

### 대안 스케치

아래는 보고서에서 비교한 설계 대안이다. 현재는 A의 궤도 조작에 C의 명판 목록과 직교 관찰 기능을 조합했다.

**대안 A — up을 고정한 궤도 카메라**

`[큰 관찰 화면] + [회전·이동·거리 조절]` 형태이다. 기존 조작에 익숙한 사용자가 적응하기 쉽고 외형을 둘러보기 좋다. 다만 내부의 작은 명판을 찾아갈 때는 회전 중심을 직접 옮겨야 한다.

**대안 B — 샌드박스 카메라와 설정 패널**

`[자유 이동 화면] + [속도·FOV·감도]` 형태이다. 관찰자가 직접 명판 앞으로 이동하고 현재 위치에서 시선을 바꿀 수 있다. 내부 탐색에는 유리하지만 조작에 익숙해져야 하며, 멀리 떨어진 지점까지 이동하는 부담이 있다.

**대안 C — 명판 선택과 전면·측면 직교뷰의 조합**

`[원근·전면·측면 버튼] + [큰 관찰 화면] + [P1~P6·O1/O2 목록]` 형태이다. 명판 선택으로 접근 과정을 줄이고 직교뷰로 구조를 비교한다. 화면을 나누면 작은 명판을 보여 줄 공간이 줄어들므로 하나의 큰 화면에서 뷰를 전환한다.

### 어떤 대안을 선택·조합했는가

| 대안 | 작은 명판에 접근 | 화면 방향 유지 | O1/O2 정밀 비교 | 현재 반영 여부 |
| --- | --- | --- | --- | --- |
| A 고정 up 궤도 | 중심 이동 필요 | 가능 | 별도 직교뷰 필요 | 기본 조작과 수평 회전 반영 |
| B 샌드박스 | 위치를 직접 이동 | 가능 | 원근뷰만으로는 한계 | 이전 버전으로 보관 |
| C 명판 선택 + 직교 | 선택하여 자동 접근 | 가능 | 적합 | 목록·반투명·직교 전환 구현 |

실제 구현은 **A의 고정 up 궤도 카메라에 C의 명판 선택과 직교뷰를 조합**했다. P1~P6은 명판이나 목록을 눌러 접근하고, 가림은 반투명으로 해결한다. O1/O2는 직교 비교 버튼으로 관찰하며, 비교 후 원근 관찰 위치로 돌아올 수 있게 했다.

## 실제 구현한 카메라·투영·입력 방식

### eye, target, up과 회전 중심은 어떻게 정했는가

원근 관찰에서 `target`은 회전 중심이고 `eye`는 target에서 거리만큼 떨어진 카메라 위치이다. yaw로 좌우만 회전하며 eye와 target의 높이는 같다. `up=[0,1,0]`을 고정해 기둥과 층이 기울어지지 않게 했다. 명판을 선택하면 target은 명판 중심, yaw는 명판 정면 방향으로 바뀐다.

[카메라 조작 코드](improved/d04-inspection-controls.js)의 핵심 부분이다.

```javascript
function camera() {
  if(state.mode!=='orbit') {
    const v=views[state.mode],offset=state.mode==='front'?[0,0,1]:[1,0,0];
    return {eye:v.target.map((n,i)=>n+offset[i]*(radius*2+1)),target:[...v.target],
      up:[0,1,0],orthographic:true,halfHeight:v.halfHeight,near:.02,far:radius*4+10};
  }
  return {eye:[state.target[0]+Math.sin(state.yaw)*state.distance,state.target[1],
    state.target[2]+Math.cos(state.yaw)*state.distance],target:[...state.target],up:[0,1,0],
    fov:state.fov,near:.02,far:Math.max(180,state.distance+radius*2+10)};
}
```

### 초기 위치와 FOV는 어떻게 정했는가

모델 경계 상자의 중심은 `C=(3.25,4.575,0)`이다. 반지름 R은 경계 상자 대각선 길이의 절반으로 잡았다. 전체 모델을 포함하는 구가 화면에 들어가도록 가로·세로 중 작은 반화각을 사용한다.

```text
R = length(max − min) / 2
세로 반화각 αy = FOV / 2
가로 반화각 αx = atan(tan(αy) × aspect)
d = 1.08 × R / sin(min(αx, αy))
eye = C + [sin(yaw) × d, 0, cos(yaw) × d]
```

초기 yaw는 0.6 rad이고 수직 FOV는 45°이다. `1.08`은 전체 보기의 여유 공간을 준다. Home을 누르면 현재 화면 비율로 거리를 다시 계산한다. 휠은 FOV 대신 거리를 바꾸며 near는 0.02 m, far는 최소 180 m이다. 직교뷰에서 명판으로 접근할 때는 현재 표시 크기에 맞춘 FOV에서 원근 FOV로 보간한다.

### 원근 투영과 직교 투영은 어떻게 사용했는가

원근 관찰 화면은 **원근 투영**이다. 가까운 물체가 크게 보여 이동과 공간의 깊이를 파악하기 쉽다. 기존 렌더러의 `M4.lookAt`과 `M4.perspective`를 그대로 사용했다.

전면·측면 화면은 **직교 투영**이다. 제공 렌더러의 `drawView`와 이전 버전의 직교뷰 상태 관리·입력을 활용했다. O1/O2 버튼은 비교 대상에 맞춰 중심과 표시 범위를 정한다. FOV 대신 화면 세로 범위의 절반인 `halfHeight`로 확대 정도를 정한다. 값이 작을수록 좁은 범위가 크게 보인다.

직교뷰의 첫 진입과 전체 보기의 목적지는 모델 중심이다. `halfHeight`는 모델 높이의 절반과 화면 비율을 고려한 가로 범위 중 큰 값에 1.1을 곱한다. 전면은 X축 범위, 측면은 Z축 범위를 가로 크기로 사용한다.

[렌더러 코드](improved/d04-inspection-viewer.js)의 핵심 부분이다.

```javascript
M.lookAt(view,camera.eye,camera.target,camera.up||[0,1,0]);
if(camera.orthographic){
  const half=camera.halfHeight||8;
  M.ortho(projection,-half*w/h,half*w/h,-half,half,camera.near||.02,camera.far||180);
}else{
  M.perspective(projection,(camera.fov||controls.state.fov)*Math.PI/180,
    w/h,camera.near||.02,camera.far||180);
}
M.multiply(vp,projection,view);
```

### 뷰를 전환할 때 원근 카메라 상태는 어떻게 기억하는가

`state.target`, `state.distance`, `state.yaw`, `state.fov`는 원근 관찰용으로 유지한다. 직교뷰의 중심과 표시 범위는 `views.front`, `views.side`에 따로 저장하므로 이동·확대·전체 보기 후에도 `orbit`으로 돌아오면 이전 원근 상태가 복원된다.

```javascript
function setMode(mode) {
  if(!['orbit','front','side'].includes(mode)||mode===state.mode)return;
  transition=null;clearInput();state.mode=mode;
  if(mode!=='orbit'&&!views[mode])views[mode]=overviewPose();
  state.actions++;changed('mode');canvas.focus({preventScroll:true});
}
```

직교뷰에 처음 들어갈 때만 전체 보기 상태를 만든다. 이후 전면과 측면을 오가면 각 뷰의 이동·확대 상태가 유지된다. 명판 선택은 새 원근 관찰 대상을 지정하는 동작이므로 이때는 원근 카메라도 변경한다.

### 입력과 명판 선택은 어떻게 처리했는가

원근뷰의 드래그는 좌우 변화량만 사용한다. Shift 또는 오른쪽 드래그는 화면 평행 이동이고, 직교뷰에서는 일반 드래그도 이동이다. 포인터가 5 CSS 픽셀 이상 움직이면 드래그로 구분해 클릭 접근을 막는다. 창 전환·포커스 상실·뷰 전환 시에는 입력 상태를 비운다.

```javascript
function turn(dx) {
  if(!dx)return;
  transition=null;
  state.yaw-=dx*.006;
  state.yaw=Math.atan2(Math.sin(state.yaw),Math.cos(state.yaw));
  changed();
}
```

직교뷰의 WASD는 화면 방향으로 8 m/s 이동하며, 입력 벡터 정규화와 0.05초 dt 제한을 적용한다. 전면의 오른쪽 벡터는 `[1,0,0]`, 측면은 `[0,0,-1]`이다. 드래그 이동량은 `2 × halfHeight / 화면 높이`로 환산해 확대 상태에서도 장면이 손을 따라 움직이게 했다.

명판 클릭은 화면 좌표에서 광선을 만들고 명판 사각형과의 교차를 검사한다. 불투명 상태에서는 구조물의 경계 상자로 가림을 확인하고, 반투명 상태에서는 구조물 가림을 무시한다. 오른쪽 목록은 보이지 않는 명판도 선택할 수 있다.

```javascript
focusFromList(id){
  const sign=model.signs.find(s=>s.id===id);if(!sign)return;
  api.selectSign(sign,{overview:!api.visibleSign(id)});
}
```

명판 접근 거리는 크기·FOV·화면 비율로 결정한다. 카메라를 명판 표면에 겹치지 않고 글자를 읽을 수 있는 거리에 둔다.

```javascript
const tan=Math.tan(fov*Math.PI/360);
const to={target:[...sign.position],yaw:sign.yaw,fov,
  distance:Math.max(.4,1.8*Math.max(sign.size[1]/(2*tan),sign.size[0]/(2*tan*aspect())))};
startTransition(overview?overviewPose():to,
  {stage:overview?'overview':'focus',next:overview?{to,delay:.18}:null});
```

접근과 전체 보기는 각각 약 0.85초 동안 시작·끝에서 느려지는 곡선으로 보간한다. 가려진 명판의 목록 버튼은 반투명을 켜고 전체 보기까지 이동한 뒤 0.18초 대기하고 접근한다. yaw는 짧은 회전 방향을 선택하며, 직접 조작하면 남은 이동을 취소한다.

반투명 모드에서는 구조물을 알파 혼합하고 깊이 기록을 끈 뒤 명판을 불투명하게 그린다. 선택 외곽선은 원본 명판보다 약간 큰 사각형의 가장자리를 초록색으로 그려 표시한다. 모델의 크기나 명판 내용은 변경하지 않았다.

## 같은 8건의 개선 전후 비교

### 전면·측면 직교 캡처

현재 개선 버전의 O1·O2 비교 버튼을 눌러 촬영한 화면이다. 두 비교 대상을 포함하도록 중심과 표시 범위를 맞추며, WASD·드래그·휠로 추가 조절할 수 있다.

![현재 개선 버전의 전면 직교뷰](images/front-current.png)


O1의 전면 직교 화면이다. 파랑 A와 주황 B의 상단이 같은 높이에 있고 폭도 같다. 두 패널은 z 위치가 다르지만, 직교 투영에서는 깊이 때문에 크기가 달라지지 않는다.

![현재 개선 버전의 오른쪽 측면 직교뷰](images/side-current.png)

O2의 오른쪽 측면 직교 화면이다. 이 시점에서는 화면 왼쪽이 건물 앞쪽인 +z 방향이다. 파랑 A의 전면 끝이 주황 B보다 더 왼쪽에 있다.

```text
O1: A·B 폭 = 1.2 m, 상단 y = 2.6 + 1.6/2 = 3.4 m
O2: A 전면 z = 0 + 2/2 = 1.0 m
    B 전면 z = −0.6 + 2/2 = 0.4 m
    A가 +z 방향으로 0.6 m 더 돌출
```

현재 개선 버전은 버튼으로 직교뷰를 사용할 수 있다. 아래 코드는 기존 비교 이미지의 시점을 각 버전에서 정확히 재현할 때 사용하는 방법이다. `viewer.render`를 지정한 동안은 고정된 캡처용 카메라를 사용하므로, UI 조작으로 돌아오려면 `viewer.render = null`로 해제해야 한다. 투영 비율은 현재 캔버스 비율을 따른다.

```javascript
const viewer = window.InspectionViewer;
const front = {
  eye: [-5.3, 2.6, 16], target: [-5.3, 2.6, 6], up: [0, 1, 0],
  orthographic: true, halfHeight: 2.1
};
const side = {
  eye: [23, 4.75, -0.3], target: [10.8, 4.75, -0.3], up: [0, 1, 0],
  orthographic: true, halfHeight: 1.6
};
viewer.render = () => viewer.drawView(front); // O1 전면
// viewer.render = () => viewer.drawView(side); // O2 측면
// viewer.render = null; // 기본 탐색 화면으로 복귀
```

### 개선 전후 기록

8건 모두 버튼형 관찰이 가능해지면서 사용자가 카메라 조작에 크게 시간을 쏟지 않아도 되며, 반투명을 추가하면서 사용자가 대략적인 명판의 위치도 파악할 수 있었다.

### 측정의 한계

기본 버전의 `actions`는 드래그 시작·휠·키 이벤트 등을 센다. 현재 개선 버전은 클릭 접근 한 번으로 여러 카메라 값을 바꾸며 자동 이동 프레임은 횟수에 더하지 않는다. 

현재 improved의 8건에 대한 관찰 시간은 별도로 기록하지 않았다. 위 소감과 자동 시점 지정 캡처만으로 시간 단축이나 오조작·피로도 감소를 수치화할 수는 없다. 버전별 실행 순서와 연습 횟수도 통제하지 않아 학습 효과를 분리하기 어렵다.

직교뷰의 키보드 이동은 20 FPS 미만에서 dt 제한 때문에 느려질 수 있다. 카메라 이동에는 충돌 처리가 없어 벽을 통과할 수 있다.

목록 선택은 이전 자유 이동의 장거리 이동 부담을 줄이지만, 자동 접근만으로 주변 구조의 위치 관계를 충분히 파악했는지는 별도 확인이 필요하다. 
명판 관측만을 하는 상황을 가정했기 때문에 상하 회전을 제한했으나 명판 외의 구조를 위아래 각도에서 보는 데에는 한계가 있다.

## 추가 수정 전후의 기록

### 1차 수정 — 명판 중심 인터페이스로 교체
직접 이동하는 조작보다 P1~P6·O1·O2를 관찰하기 쉽게 하는 데 초점을 맞춰 명판 선택·반투명·목록을 구성했다. 전면·측면 직교뷰와 상태 복원은 유지했다.

### 2차 수정 — 자동 접근과 전체 보기 애니메이션

처음 명판 선택은 즉시 카메라를 옮겼다. 이후 이동 과정을 따라갈 수 있도록 애니메이션을 넣고, 화면 밖이거나 가려진 명판도 오른쪽 목록에서 선택할 수 있게 했다. 전체 보기 역시 부드럽게 이동하도록 수정했다.

| 항목 | 추가 수정 전 | 현재 버전 |
| --- | --- | --- |
| 명판 선택 | 즉시 정면으로 이동 | 약 0.85초 동안 부드럽게 접근 |
| 보이지 않는 명판 목록 | 버튼 비활성화 | 반투명 켜기 → 전체 보기 → 명판 접근 |
| Home / 전체 보기 | 카메라 즉시 초기화 | 원근·직교 모두 약 0.85초 이동 |
| 단계 연결 | 명판 접근만 처리 | 전체 보기 이동 → 0.18초 대기 → 접근 |
| 직접 조작 | 즉시 카메라 변경 | 자동 이동과 남은 단계를 취소하고 조작 |
| 뷰 복귀 | 원근 상태 보존 | 직교 이동·전체 보기 후에도 보존 |

현재 버전은 명판 선택, 반투명, 외곽선, 직교 상태 복원, 애니메이션 연결·중단 등을 포함한 36개 브라우저 검증을 통과했다. 실제 Chrome 입력 경로에서도 전체 보기 버튼과 명판 목록의 이동을 확인했다. 이는 기능 검증이며 사용자 관찰 시간 측정과는 다르다. 조작과 구현 설명은 [INTERFACE.md](improved/INTERFACE.md)에 정리했다.

### 구현 과정에서 확인되는 제안과 결정

| 제안 또는 요청 | 실제 반영 내용 | 검토할 대안·이유 |
| --- | --- | --- |
| 사용자: baseline 조작 유지, 좌우 회전만 허용 | 드래그·평행 이동·휠과 고정 up 궤도 카메라 | 자유 이동보다 기존 조작의 익숙함과 방향 유지에 초점 |
| 사용자: Space 반투명과 명판 클릭 접근 | 가림을 해제하고 명판 중심·정면으로 이동 | 구조물을 완전히 숨기기보다 주변 형태를 남기도록 선택 |
| 사용자: 선택 명판에 초록색 외곽선 | 자동 접근 중 유지, 직접 조작 시 해제 | 별도 답 표시보다 현재 관찰 지점을 식별하도록 구성 |
| 사용자: Old의 전면·측면 직교뷰 유지 | WASD·드래그·확대와 원근 상태 보존, O1/O2 버튼 | 원근 관찰과 정확한 폭·높이·돌출 비교를 함께 지원 |
| Codex: 명판 크기·FOV에 맞춘 접근 거리와 짧은 방향 회전 | 읽기 쉬운 거리 계산, yaw 보간 | 모든 명판에 같은 거리나 긴 회전 경로를 적용하는 대안과 비교 |
| 사용자: 이동 애니메이션과 숨은 명판 목록 선택 | 현재 시점 → 전체 보기 → 명판 접근, 직접 조작 시 취소 | 즉시 전환보다 이동 과정을 보여 주고 수동 조작을 우선 |

직접 사용한 소감을 바탕으로 자유 이동 중심에서 명판 선택 중심으로 바꿨다. 제공 모델을 유지하면서 접근 과정과 가림을 개선했고, 구조 비교는 직교뷰로 보완했다. 현재 방식의 관찰 시간과 공간 이해도는 추가 측정이 필요하다.
